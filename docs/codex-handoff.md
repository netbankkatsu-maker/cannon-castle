## ユーザーが作りたいもの

大砲の弾を撃って3Dの城を物理的に崩す、スマホ向けインクリメンタルゲーム。コインで強化し、砲台を増やして自動化する。

重要な希望：

1. 城をタッチすると、その場所へ直接発射。通常の発射ボタンは表示しない。
2. 不要な説明やボタンを増やさない。スマホゲームらしいUI、片手で分かる配置。
3. リロード中はバーを表示し、中央に残り秒数。
4. 崩れた城は逆再生のように瓦礫が戻り、組み上がる。
5. 追加砲台を買うとカメラが城の上へ滑らかに移動。マスを選び、自動砲撃の大砲を設置。
6. PWA対応を維持。サブエージェントによるUI/UX評価を行う。

## 技術構成と起動

素のHTML / CSS / JavaScript ES Modules。React・Next.js・DB・サーバーAPIは使っていない。
Three.js 0.160.1 と cannon-es 0.20.0 を固定URLの jsDelivr からimport。
Node.js 20以上、npm依存パッケージのインストール不要。

```sh
git clone https://github.com/netbankkatsu-maker/cannon-castle.git
cd cannon-castle
npm test
npm run dev
```

ローカルは http://localhost:3000 。ビルドは `npm run build`。
`scripts/build.mjs` が src を dist へコピー。Vercelは Other / npm run build / dist。環境変数は不要。

## 実装済みの挙動

### 砲撃・強化

- タッチのraycastで生きているブロックを照準にし、砲弾を発射。
- 砲弾は重力を補正した3D弾道。爆風でHPを減らし、物理インパルスで崩す。
- 威力・連射・主砲自動の3種。主砲自動は主砲の自動化で、追加砲台とは別。
- HPを減らした割合に応じてコインを獲得。クリア時に追加ボーナス。
- リロード：初期1.15秒、連射強化で短縮、下限0.22秒。バーは装填済み割合。

### 破壊率

- 各ブロック初期HP100。
- 破壊率 = 100 × (1 − 残りHP合計 / 初期HP合計)。
- 元の位置から0.8以上移動したブロックは一度だけ60ダメージ。
- 吹き飛んだ瓦礫もHPが残る限り狙える。HP0だけ消える。
- 95%破壊したら最後5%を自動回収し、100%でクリア。
- 大きく場外へ飛んだブロックも回収。次の城のボタンはクリア時だけ。
- 旧バグ：移動したブロックを破壊扱いにして照準対象から除外し、最後まで壊せなかった。再発させない。

### 城の再生

- 「組み直す」と次ステージで瓦礫の位置・回転から元の配置へ補間。
- 約1.4秒、ブロックごとに少しずらして逆再生風に戻る。
- 実時間で進め、ブラウザのフレーム制限でも完了できる。
- 再生中は砲撃・購入を停止。OSの動きを減らす設定では即時復元。

### 追加砲台

- 初回120コイン、以後floor(120 × 1.7^設置数)。
- 配置状態：battle → entering → placement → leaving → battle。
- カメラ移動約1.1秒。配置・移動中は戦闘を一時停止。
- x=-9〜9、z=-10〜14、3間隔のマス。城・主砲・既設砲台を除外。
- マスをタッチした時だけ費用を消費。キャンセル無料。
- 追加砲台は自動で残ったブロックを狙う。再生・次ステージでも残る。
- 追加後は通常カメラを引いて、端の砲台も映るよう調整済み。

### PWA・更新

- ホーム画面追加、standalone、Service Worker、PNGアイコン。
- 初回オンラインでアプリとCDNモジュールのキャッシュが完了した後、オフライン起動を想定。
- 現在キャッシュ名 cannon-castle-v7。主要アセットは ?v=7。
- アプリのファイルはnetwork-first、CDNはcache-first。
- 以前、古いSWのcache-firstで新HTMLと旧CSS/JSが混ざった。更新時はキャッシュ名とHTMLのアセットURLのバージョンを揃える。
